# 设计决策

记录这个工具为什么长成现在这样，方便后来的维护者判断「能不能改」。

---

## 1. 目标与非目标

**目标**：让普通用户看清 C 盘占用，并安全地删掉「删了会自动重建」的东西。

**非目标**：

- 不做「一键加速」「注册表清理」这类无法验证收益的功能。
- 不做驱动管理、启动项管理、软件卸载。
- 不删除任何个人数据，即使这会少释放几十 GB。

## 2. 为什么是 WinForms + 系统自带 csc

- 目标用户是 Windows，程序需要删除系统目录，天然需要管理员权限。
- Electron / Python 打包体积大、启动慢，还要带运行库；.NET Framework 4.8 是
  Windows 10 1903+ / 11 的组成部分，等于零依赖。
- 系统自带的 `csc.exe` 足够编译，不需要 Visual Studio 或 .NET SDK，contributor 门槛低。
- 代价是只能用 C# 5 语法（没有字符串插值、`?.`、`nameof`），代码里刻意避开了这些。
- UI 全部自绘（见 `Theme.cs` / `Widgets.cs`），避免引入第三方控件库。

## 3. 为什么是永久删除，而不是隔离区

v1 的决策就是永久删除，v2 沿用。理由：

- 隔离区需要额外的磁盘空间，而这台机器的诉求是「尽量多释放」。
- 移入隔离区的耗时远高于删除，用户会误以为程序卡住。
- 永久删除 + 「演练模式」+ 「输入 DELETE」已经提供了足够的确认环节。

如果以后要做隔离区，建议作为可选开关，默认关闭，并且隔离区必须放在同盘以外，
否则无法真正释放空间。

## 4. 为什么个人数据只统计

删除聊天记录、文档、游戏本体是不可逆的数据损失，而且用户往往在几天后才意识到。
因此这些目录：

- 仍然会被扫描、显示体积（用户需要知道空间去哪了）；
- 但 `Deletable = false`，界面上没有勾选框；
- 也不提供任何隐藏开关把它们变成可删除。

正确做法是引导用户迁移（Steam 库迁移、微信存储位置、Xbox 应用移动）。

## 5. 白名单校验

`Util.IsSafeDeletePath` 是最后一道防线，规则：

1. 必须是 `C:\` 下的绝对路径；
2. 不含 `..`、不含通配符；
3. 不能等于保护名单里的路径（盘根、Windows、System32、WinSxS、Program Files、
   ProgramData、Users、用户配置根等）；
4. 不能是重解析点；
5. 路径必须存在时才做属性检查。

清理开始前对**所有**选中项统一校验，任意一条失败就整体中止，避免「删了一半发现
路径不对」。这条规则不允许为了「方便」而放宽。

## 6. 扫描策略

- **单遍遍历**：一次走完 C 盘，同时完成目标归属、目录聚合、大文件排行，避免重复 I/O。
- **目录聚合只到第 4 层**：`C:\Users\<name>\AppData\Local` 这一层足够定位大户，
  再深会占用大量内存且没有展示价值。
- **硬链接按路径计数**：WinSxS 里同一份文件被多个路径引用，按路径累加会重复计算。
  .NET 没有便宜的「实际占用」接口，所以如实注明「含硬链接重复计算」。
- **跳过重解析点**：防止死循环，也防止把链接目标算进体积。
- **权限不足不中断**：记录到 denied 列表，最后在报告里说明；管理员模式下会补齐。

## 7. 分类与目标

六个分类对应六种决策：

| 分类 | 决策依据 |
|------|----------|
| 系统垃圾 | 删了系统会自己重建，风险最低 |
| 开发与运行缓存 | 删了重新下载/构建，项目本身不受影响 |
| 系统组件 | 只能通过 DISM / 还原点接口处理，不能手删 |
| 游戏与大型软件 | 着色器缓存可删，游戏库本体只统计 |
| 第三方应用缓存 | 应用自己的缓存，删除不影响账号数据 |
| 用户大文件 | 只统计，迁移建议 |

目标 ID（`SYS-01`、`DEV-06`…）保持稳定，v1 的 JSON 计划可以继续导入。

## 8. 界面决策

- 左侧导航 + 内容区，而不是单页滚动：150% 缩放下单页会把表格挤得很窄。
- 「可清理」页保留分类列的小圆点，让用户知道当前项属于哪一类。
- 勾选状态存在数据对象上，而不是表格行上，这样切换分类筛选不会丢选择。
- 风险用彩色徽章而不是文字，扫一眼就能分辨。
- 概览页的卡片式布局沿用 HTML 报告的视觉语言，降低两套界面的认知差。

## 9. 已知取舍

| 取舍 | 原因 | 可能的改进 |
|------|------|------------|
| 未签名 | 证书成本 | 购买代码签名证书，或在 Release 提供校验和 |
| 没有自动更新 | 避免联网与后台行为 | 手动检查更新即可 |
| 没有隔离区 | 见第 3 节 | 可选开关 |
| 只支持 C 盘 | 需求明确，避免误删其他分区 | 多盘支持需要重新设计目标表 |
| 单显示器布局 | 窗口居中，未记忆位置 | 保存窗口位置到配置 |

## 10. 未来可以做的

1. 可选隔离区（7 天可恢复）。
2. 代码签名 + Release 校验和。
3. 导出报告时附带「本次扫描快照」，支持两次扫描对比。
4. 针对 NVIDIA 缓存的内置定时提醒。
5. 更细的开发者缓存识别（JetBrains、Go、Cargo 等已有，可继续扩充）。
